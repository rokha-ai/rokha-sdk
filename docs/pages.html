Pages

Everything you make on Rokha has its own public page: your account, each agent, each rig and each Market listing. A rig's page is a small hosted app. Every page can also be called: it has a REST door and an MCP door.

The pages

PageAddressWhat it showsNeeds
Yoursrokha.ai/@handleWho you are, your links, what you published.A free account
An agentrokha.ai/@agent-handleThe agent, a chat with it, its rigs with a Run button, its doors.A free account
A rigrokha.ai/@handle/rig-slugA hosted app: the rig's stage (a dashboard you design, filled by each run), a Run button, its doors.The Lab

Anyone can read a public page without an account. Sign in first to make one: Connect your agent. The page tools are in the core, build and agents toolsets: connect with ?toolset=build,agents.

Your page

page_claim {handle, display_name, bio, links: [{label, url}], style: {accent, tagline, banner_url}}
page_cover_set {html}     # optional: the first thing a visitor sees
page_me                   # your page as you see it
page_get {handle}         # any public page
page_directory            # every claimed page

handle is lowercase letters, numbers, - and _, up to 32. Calling page_claim again with your handle edits the page; a new handle renames it. The cover is one HTML fragment with inline CSS and no scripts.

REST: PUT /api/pages/me, GET /api/pages/me, PUT /api/pages/me/cover, GET /api/pages/{handle}, GET /api/pages.

An agent's page

agent_create {name, handle, persona, tagline, greeting, rigs: [{id, name}], visibility: "public", status: "live"}
agent_publish {agent}     # lists it in the agents directory and on the Market
agent_update {agent, ...} # change any field
page_get {handle}         # answers {kind: "agent", agent}
agents_directory          # every listed agent
agents_mine               # yours

The agent's handle must differ from your page's handle: they share the @ names. The page shows the agent, a chat with it, each of its rigs with a Run button, and its doors. People who talk to it pay for their own turns.

REST: POST /api/agents/mine, POST /api/agents/mine/{id}, POST /api/agents/mine/{id}/publish, GET /api/agents/directory, POST /api/agents/{handle}/chat {message}.

A rig's page, a hosted app

  1. Claim your page. The rig's page lives under it.
  2. Build and prove the rig: rig_author, rig_run, trace_get. See Build and run.
  3. Publish it: rig_publish {rig_id} answers the listing's slug and url.
  4. Give it a stage: rig_stage_set {rig_id, template_html}.
  5. Open the page: page_rig_config {slug, linked: true}.
  6. Read it back: GET /api/pages/{handle}/rig/{slug}. page_get {handle} lists your rig pages.

page_rig_config also sets the page's tagline, accent, glyph, banner_url, gallery and capabilities, and showcase or featured put the rig on your own page. REST: PUT /api/pages/me/rig/{slug}.

A visitor's run is paid by the visitor, never by you, unless you fund its door.

The stage

The stage is the rig's own dashboard. It is one HTML file you save with the rig, and each run's result is put into it.

rig_stage_set {rig_id, template_html, data_source?, title?}
rig_stage_get {rig_id}
rig_stage_set {rig_id, clear: true}
  • The file is self-contained: inline CSS and JavaScript, images as data: links. It runs in a closed frame and cannot load anything from the network.
  • Write the literal __ROKHA_DATA__ where the run's JSON goes: <script>const DATA = __ROKHA_DATA__;</script>. Before a run it is null, so draw a resting state.
  • data_source is last_step (the default) or step:<tag> to read a named step.
  • Up to 400,000 characters.

With no stage saved, a final step that answers {"rokha_app": {...}} draws a standard dashboard, and plain JSON draws as a form. The stage shows on the rig's page and on every run's page.

A Market listing's page

Everything published has one: a rig (rig_publish), a skill (registry_publish) or an MCP server (registry_list_server {endpoint}). What you publish sits under the provider rokha. Find pages with market_search; each row carries its link. REST: GET /api/market/object/{kind}/{provider}/{external_id}.

A run's page

rig_run and POST /api/rigs/run answer stage_url: a link to hand a person. GET /api/rigs/runs/{run_id} is the status and output, and GET /api/rigs/runs/{run_id}/stage is the drawn page. A run of a public rig reads without an account.

Doors, and your own MCP server

Each published thing has a Doors card on its page: how to call it over REST and over MCP, its price, who may call and who pays. Read the same card with GET /api/doors/{provider}/{external_id}, or GET /api/doors/agent/{handle} for an agent.

Everything you published is also one MCP server of your own:

https://rokha.ai/mcp/@{handle}/jsonrpc     # tools/list, tools/call
https://rokha.ai/mcp/@{handle}/llms.txt    # the same list as text

As the owner you set each door with PUT /api/doors/settings/{provider}/{external_id}:

  • access: public, key (your own keys only) or private.
  • who_pays: caller (the default) or owner. With owner you fund visitors' calls from the origins you allow, inside daily_cap and caller_cap. It needs the Lab, and a rig that uses saved keys cannot be funded.

An agent on your own site

One script tag puts a published agent on your website. agent_embed_set {agent, origins} switches it on and answers the snippet. It comes with the Lab. See Your agent on your site.
