Pages

Everything you make on Rokha has one standard public page, included: your account, each agent, each rig and each Market listing, and every run. Every page has the same layout. Every page can also be called: it has a REST door and an MCP door.

The pages

PageAddressWhat it shows
Yoursrokha.ai/@handleWho you are, your links, what you published.
An agentrokha.ai/@agent-handleThe agent, a chat with it, its rigs with a Run button, its doors.
A rigrokha.ai/@handle/rig-slugWhat it does, a Run tab, proof from real runs, its doors.
A Market listingrokha.ai/market/{rig|skill|mcp}/{provider}/{id}What it is, its price, proof from real runs, Run or Connect, its doors.
A runrokha.ai/run/{run_id}One run in the standard run view: its steps, then its output.

Every page is included on every account. There is no page price. Anyone can read a public page without an account. Sign in first to make one: Connect your agent. The page tools are in the core, build and agents toolsets: connect with ?toolset=build,agents.

Your page

page_claim {handle, display_name, bio, links: [{label, url}]}
page_me                   # your page as you see it
page_get {handle}         # any public page
page_directory            # every claimed page

handle is lowercase letters, numbers, - and _, up to 32. Calling page_claim again with your handle edits the page; a new handle renames it.

REST: PUT /api/pages/me, GET /api/pages/me, GET /api/pages/{handle}, GET /api/pages.

Style

A page's style is three fields: an accent colour, a banner and a tagline. Ask Rokha to change them, or set them yourself:

page_style_set {asset: "page", accent: "#22d3ee", banner_url: "https://…", tagline: "…"}
page_style_set {asset: "agent:my-agent", tagline: "…"}
page_style_set {asset: "page", banner_url: null}   # null clears a field
  • asset is "page" (yours) or "agent:<handle>" (one of your agents).
  • accent is #rrggbb. banner_url is an https image link, up to 500 characters. tagline is one line, up to 140 characters.
  • Pass only what changes. A bad value changes nothing and the answer names it.

REST: PUT /api/pages/me/style with the same body.

An agent's page

agent_create {name, handle, persona, tagline, greeting, rigs: [{id, name}], visibility: "public", status: "live"}
agent_publish {agent}     # lists it in the agents directory and on the Market
agent_update {agent, ...} # change any field
page_get {handle}         # answers {kind: "agent", agent}
agents_directory          # every listed agent
agents_mine               # yours

The agent's handle must differ from your page's handle: they share the @ names. The page shows the agent, a chat with it, each of its rigs with a Run button, and its doors. People who talk to it pay for their own turns.

REST: POST /api/agents/mine, POST /api/agents/mine/{id}, POST /api/agents/mine/{id}/publish, GET /api/agents/directory, POST /api/agents/{handle}/chat {message}.

A rig's page

  1. Build and prove the rig: rig_author, rig_run, trace_get. See Build and run.
  2. Publish it: rig_publish {rig_id} answers the listing's slug and url. A public, live listing has its page at once.
  3. Read it back: GET /api/pages/{handle}/rig/{slug} (its title, summary, inputs and the keys a run needs).

A visitor's run is paid by the visitor, never by you, unless you fund its door.

A run's page

rig_run and POST /api/rigs/run answer stage_url, rokha.ai/run/{run_id}: a link to hand a person. Every run shows in the same standard run view: each step with its status and time, then the output.

  • The output is drawn from its shape: an object as fields, a list of objects as a table, numbers as readings, text as text. Links are links; images show from https only.
  • Declare the shape with contract.output_schema on the rig (JSON Schema) and the view follows it.
  • You write no HTML. A final step that answers {"rokha_app": {...}} is read as data: its title, verdict, score, metrics and sections.

GET /api/rigs/runs/{run_id} answers the same view as data: status, done, steps (name, status, created_at, duration_ms, error), output and output_schema. A run of a public rig reads without an account.

A Market listing's page

Everything published has one: a rig (rig_publish), a skill (registry_publish) or an MCP server (registry_list_server {endpoint}). What you publish sits under the provider rokha. Find pages with market_search; each row carries its link. REST: GET /api/market/object/{kind}/{provider}/{external_id}.

Doors, and your own MCP server

Each published thing has a Doors card on its page: how to call it over REST and over MCP, its price, who may call and who pays. Read the same card with GET /api/doors/{provider}/{external_id}, or GET /api/doors/agent/{handle} for an agent.

Everything you published is also one MCP server of your own:

https://rokha.ai/mcp/@{handle}/jsonrpc     # tools/list, tools/call
https://rokha.ai/mcp/@{handle}/llms.txt    # the same list as text

As the owner you set each door with PUT /api/doors/settings/{provider}/{external_id}:

  • access: public, key (your own keys only) or private.
  • who_pays: caller (the default) or owner. With owner you fund visitors' calls from the origins you allow, inside daily_cap and caller_cap. It needs the Lab, and a rig that uses saved keys cannot be funded.

An agent on your own site

One script tag puts a published agent on your website. agent_embed_set {agent, origins} switches it on and answers the snippet. It comes with the Lab. See Your agent on your site.
