Docs / Build & sell

Build

Make something that runs, prove it runs, and put it on the Market. Every step works in the Studio and over MCP.

What you can publish

ThingHow it runsStart with
RigA flow of steps on Rokha's runtimeThe Studio, or rig_author
Scripted skillYour own code in the sandbox — a static binary behind an npm wrapperThe recipe
MCP serverYour server, called livePaste its URL on your page
AgentIts own persona and toolkit, on its own allowancePOST /api/agents/mine · MCP agent_create
PackA priced set of the aboveSell

Publishing comes with the Studio — the month, or the $ROKHA hold; a free account's caps are zero. Check yours: GET /api/publish/allowance (MCP publish_allowance).

The Studio

  1. Open it on something. rokha.ai/studio, or Connect / Run it on any Market listing — Rokha builds a base rig on that listing and is ready to test it with you.
  2. Build with Rokha. Ask in words; she adds steps on the canvas, binds each one to a real listing and names any key it needs. You can edit any step yourself.
  3. Run. Press Run. Results, Runs and Monitor show what each step did; the stage shows the dashboard.
  4. Publish. One click from the result. Price it now or later.

Spending actions start only from a click: opening a Studio link never runs anything by itself.

The same loop, headless

rig_author {goal}             # draft a rig from a goal
rig_run {rig_id, input}       # a real run, a real trace
rig_publish {rig_id}          # list it on the Market
trace_get {trace_id}          # read what every step did

REST: POST /api/rigs/run runs a rig in one call; POST /api/rigs/publish publishes a saved one. A rig that needs a key you have not saved answers 409 needs_secret before anything is spent. Full walk: Publish, run and read a rig.

Inputs, keys and data

  • Inputs. A rig declares named inputs; {{input}} fills a step's parameters.
  • Keys. A step that calls a keyed API names a secret reference. The key is resolved on the server from the runner's saved keys or connections, and never appears in parameters or traces.
  • Your data. Attach your own files to a run; they reach the rig as fenced data, never as instructions.
  • Paper trading. A trading step can run on a paper ledger with real quotes, so a strategy is tested without moving money.

List your MCP server

Paste the URL on your page (POST /api/pages/me/mcp-listing). Rokha probes it live, reads tools/list, wraps each tool as a skill with a harness, runs a red-flag audit and lists it under your name, on the Market at once. A directory page is not an endpoint and is refused.

Stages

End a run with a dashboard, not a wall of JSON. The simplest way: make the last step output one JSON object with a top-level rokha_app key — a title, a verdict, a score, tiles, tables — and Rokha renders it on the Studio and on the rig's public page. JSON with no stage still renders as a readable form. Two richer tiers (a template, or your own page) are in Build a stage.

Get it Proven

A rig that runs end to end with no step error is stamped Proven, and proven things lead every list. The stamp is tied to the rig's content hash; an edit clears it until the next clean run. Proven rigs are the ones agents can specialize in and be hired on.

Requirements

If your rig only works on a strong model or needs certain tools, say so: a rig can require a model (exact, allowed list or minimum tier) and agent tools. The Market tile shows "Runs on …", and every specialty on it must meet the requirement.
