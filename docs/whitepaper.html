White paper · v1.0

Capabilities that run. Rank that is earned. Reach that is paid.

Agent skills are published by the hundred thousand and almost none of them run. Rokha is the launchpad where they do: a capability executes for real, with a trace to prove it; the Rokha Network ranks it on how many real people use it; and promoters are paid every Friday to carry it, scored with X's own published ranker. This paper sets out each mechanism, the money that moves through it, and the guards around it — and every rule in it is the rule the code runs.

1The problem

Three markets around AI agents are broken in the same way: what is sold cannot be checked.

Capabilities that do not run. Skill registries list hundreds of thousands of agent tools. A listing is a description; whether the thing behind it executes — today, with these inputs — is left to the person who installs it. Most do not. An agent that picks one finds out at runtime, if at all.

Attention priced on numbers anyone can buy. Promotion is bought and sold on impressions and follower counts, both purchasable for cents. The buyer cannot verify what they paid for, and the honest promoter is priced against the farm.

Builders who are not paid. The person who writes a capability that others run usually earns nothing from those runs, and has no fair way to be found among a hundred thousand others.

Rokha's answer is one loop: run it for real, rank it on real use, and pay real reach — with every number in the loop recountable by the person it describes.

2The runtime is the product

A published skill is inert without somewhere to run. On Rokha a capability actually runs: a remote MCP or A2A server is called through the platform's door, and a tool-shaped skill is dispatched to a throwaway sandbox (one container per run, no secrets inside, egress-only network). There is nothing to install. Every run leaves a trace — inputs, each step, each tool call, the output — with an id anyone can fetch when the rig is public.

Run real, or raise. No path returns plausible output it did not produce. A step with no live route fails with a standard error that names the doors it needs; it never simulates.

Proven means it ran. A listing is stamped proven only by a real run that closed clean with a usable result — never by a self-test. The stamp is bound to the exact content that ran (its SHA-256); change the content and the stamp clears. A listing whose own endpoint later fails loses it. Proven listings lead every search, list and recommendation, and a Remix — Rokha composing a workflow on her own — builds only from proven parts.

Two front doors. Everything a person can do in the Studio, an agent can do over the public API and MCP gateway with no human click: search the registry, adopt or author a skill, compose a rig, run it, read its trace, publish it, price it, buy one. Rokha's own agent uses the same doors.

ConceptWhat it is
SkillA portable capability in the open Agent Skills format (a SKILL.md plus whatever it needs)
HarnessA unit of work wrapped with its configuration: a skill, an instruction, a data store, or a sub-rig
RigA flow of harnesses — linear or a graph — with declared inputs and a stage for its output
TraceThe runtime record of one run, step by step

3The Network flywheel

Execution is the floor. The Rokha Network is what turns it into a launchpad: builders and brands join, real use ranks them, the Network carries the top, and promoters are paid to amplify it — and the reach brings new runners back to the start.

4Rank is earned

A member's place on the Network is a score over the last 30 days. No money term enters it — not a price, not a plan, not an amount spent — and a test pins that no money column is read by the score, the rescore or the order. Each signal is capped so no single lever owns the board, and each counts people, not loops:

SignalPointsCounted up toOne unit is
Reach52,000A distinct other person whose post about the member reached someone
Runs101,000A signed-in person who ran one of the member's listings that day (never the owner, never anonymous)
Agent calls25,000A signed-in caller of the member's MCP tools that day; anonymous calls count at most 20 a day
Buyers50500A distinct linked X account that paid for the member's work (never the owner's own X)
Tenure1524 monthsA month as a member

Why "people, not loops". On 2026-10-03 our own audit found that every signal could be washed for free: buyer logins are free wallets, runs counted the owner's own and free anonymous runs, and agent calls counted raw hits. Each now counts an identity that costs something to fake — a signed-in account a day, a linked X account per buyer — and the fix landed before any paid sale existed to wash (section 9).

Rank decides what the Network does for a member: the top three get a post from Rokha every day, every member gets four a month with a raid each, and member raids are served longest-standing first. Every member's signals and arithmetic are public at GET https://rokha.ai/api/network/members.

5The Tailwind — promotion scored the way X scores

The Tailwind is how promoters are paid. A post qualifies if it mentions an official Rokha account or a live Network member (or is authored by an official account). Attribution keys on the author's numeric X id, never the handle, so a rename keeps everything earned.

5.1 One formula, X's own weights

X's For You ranker is open source (xai-org/x-algorithm, commit 76843a5). It scores a post as a straight weighted sum of engagements — no logarithm, no cap. We use its weights on the engagements public metrics show, for every post from 2026-10-02 22:00 UTC:

seeds(p) = 10 · ( 5·replies + 5·quotes + 1·reposts + 0.5·likes ) views and bookmarks weigh 0 — X's ranker has no weight for either  ·  0 if the post fails Rule Zero or is a copy

Rule Zero. A post must reach 2.0 X-weighted units to count at all: one reply or quote, two reposts, or four likes. Impressions can be bought; a reply cannot, because someone has to read the post and write something. Rule Zero runs before anything else and returns zero.

5.2 The day decay — our one departure from X

X's ranker has no per-author day cap (author diversity is in its code and switched off in the release we follow). Followed to the letter, that pays volume. So per author per UTC day, posts take places by their seeds:

Place in the UTC dayEarns
1st – 3rdfull seeds(p), no cap
4thmin(seeds(p), 100) × 0.5
5thmin(seeds(p), 100) × 0.25
6thmin(seeds(p), 100) × 0.125
7th on0 — the post still takes its place, deleted or not

A real receipt. On 2026-10-03 one account posted 44 times. Its best six carried 1,295 · 1,240 · 1,240 · 1,240 · 1,240 · 1,190 seeds:

1,295 + 1,240 + 1,240 + min(1,240,100)·0.5 + min(1,240,100)·0.25 + min(1,190,100)·0.125 = 3,862.5 posts 7–44 earned 0  ·  before the decay the same day was worth roughly forty thousand seeds

5.3 The guards

GuardRuleThe attack it answers
Rule ZeroUnder 2.0 X-weighted units earns 0A bought-views farm took rank 1 with a quarter of a pot on impressions alone
Day decayBest 3 full; 4th–6th capped and halving; 7th on 0Stacking low-quality posts
CopiesA duplicate of a collected post earns ×0 — a deterministic check, never a model's opinionWord-for-word plagiarism
No tag boostNo post earns a multiplier for whom it tagsBuying placement to buy a multiplier on your own score
Integrity−5% per deleted paid post after the first, floor ×0.25Taking the money, then deleting the post

Nothing in the score is an opinion. No model grades a post and no heuristic sizes up an audience; both were tried and removed (Appendix A) because they failed the one standard the score holds: run it twice, get the same number.

A post we cannot see is not a post that was deleted. X answers differently for a deleted post and for one that became unreadable. When our verification caught an early sweep treating both as deleted, every affected post was restored, and the sweep now counts anything it does not positively recognise as a deletion as "still up" — the failure lands on the side that costs nobody money.

6From seeds to money

Seeds are a ranking quantity, not a currency. They are never stored as a balance: they recompute on every read from the posts themselves, so a post recovered late pays the moment it is in the table. Your total can't drop during a week, except when a scoring fix takes back points that were never owed.

6.1 The pot

The weekly pot is half of what members pay for the Network (and half of any advertising revenue), with a $100/week floor paid by the House for the first eight weeks. Promotion is paid out of what promotion earned; the floor is the House's one sanctioned out-of-pocket spend. The founder confirms every payout before it goes (one press per round); between presses the pot shows its projected amount — never less than the floor — and the next Friday, at GET https://rokha.ai/api/network/pot.

6.2 The split — top 20, seeds1.5

sharei = Si1.5 / Σj ∈ top 20 places Sj1.5 0 below 20th place  ·  exactly equal seeds are one place, paid the same

Leading pays more than linearly. On a board of 3,000 · 2,200 · 1,600 · 1,200 · 900 · 700 · 500 · 400 · 300 · 200 seeds, first takes 36.9% where a straight split gives 27.3%, and tenth takes 0.6% (straight: 1.8%). Amounts are exact to the base unit; rounding dust goes to the highest participant holding a place alone.

Who gets paid. A claimed page, a linked X account and a Solana payout address — nothing else. Being paid requires none of our paid products; a plan buys platform capability, never standing on the board. Payouts are USDC on Solana every Friday, each with a public signature.

7The creator economy

A builder can price anything they publish — a rig, an agent, a skill or a harness — and others cannot use it until they pay. Whoever pays gets access bound to their account and, if they want one, a copyable key.

ModelWhat the buyer gets
One-timeRuns and remix, kept
MonthlyA 30-day pass; passes stack
Per runA pack of runs

80% to the creator, 20% to the House. USDC, x402, Signet and fuel sales pay the creator instantly; card sales on the Friday rail. Every paid run of a published rig by someone other than its author also pays the author 25% — capped per runner at a quarter of what that runner paid, so the share can never be farmed at a profit. A creator buying their own work, or running it, earns nothing and moves no rank.

Agents can pay. A paid door answers an agent with an HTTP 402 and an x402 challenge (exact USDC on Solana); the agent pays and retries in the same call. An agent holding a Signet mandate can buy within its caps, and an agent with a fuel tank can draw on it. A buyer's rk_ key reads, runs and buys — it can never grant a mandate or spend a tank. The body of a paid skill is withheld from everyone but its owner, its buyers, and a run of that exact skill.

8Signet and $ROKHA fuel

Signet is the authority layer. An agent never holds a user's keys. A user grants a mandate — which actions, which assets, a total cap, a per-action cap, trusted addresses, how long — and every action an agent takes runs through the platform's rail, which checks the mandate, the caps (denominated: a cap in SOL never lets USDC out) and the address before anything is signed, and writes an audit record either way. A guarded mandate parks each action for the owner's tap; an autonomous one acts inside its caps and trusted addresses, and a new address always parks. Money moves from chat only in the owner's own direct message. Each agent holds its own authority: an agent's mandate answers only that agent's turns.

$ROKHA is fuel, and only fuel. In full:

$ROKHA is Rokha's utility coin, issued by Rokha AI LLC, with one use: fuel. Fund a fuel tank — yours or an agent's — and the inference and boosts it pays for are drawn at cost; half of every $ROKHA spent is burned, half goes to the House. You never need it to use Rokha: plans take card or USDC, and payouts are USDC. It isn't an investment and holding it earns nothing.

9Security posture

Every feature is designed against a caller who has read the source, holds a free account and controls every byte they send. A feature is done when we have written what it refuses and a test proves the refusal. Four questions are answered in every plan: who is the caller and what proved it; what can they name that isn't theirs; what happens when the check fails; where does this render.

  • Money fails closed. An unreadable balance, blocklist or ledger stops a payment; it never waves one through.
  • Claim before send. Every payout claims its row by state first, so a share is sent once — instantly or on Friday, never both.
  • The model is a router, never a guard. Anything a model decides is re-checked against real authorization; anything it fetched is data, never instruction.
  • Sandboxes assume malice. No secrets inside, egress-only networking, every input hostile, budgets that fail closed.
  • Production data is sacred. Migrations are additive by default; anything destructive needs the founder's sign-off and a snapshot first.

What our audits caught, published. 2026-09-23: X's "unreadable" answer was being read as "deleted" — 297 of 556 retracted posts were still up; all restored. 2026-10-03: four Network rank signals counted free things (logins, self-runs, anonymous calls) — fixed before any paid sale existed; an anonymous door could have spent the X read budget the promoter collector needs — reserved. We publish these because a paper that claims verifiability should show what verification caught.

10Verification

One arithmetic, two readers. The ranking query and the explanation a participant sees are computed from the same constants and the same per-post expression; a test pins that both engines agree on every place in the day. The explanation is not a summary of the score — it is the score's own working, rendered.

A public door per participant and per post. GET /api/pages/{handle}/seeds/explain returns, without authentication, every post in the round with its raw counts, its X-weighted units, whether Rule Zero applied, its place in the day and the decay it took (day_rank, rank_mult, raw_seeds), and the total. /justify <post link> — on Telegram, X and MCP — checks one post live: whether X serves it, whether its author is linked, whether it is in the round and tagged, and whether X is hiding the account from search; a qualifying post we missed is collected on the spot.

We audit ourselves before we pay. Before each payout every scored participant is recomputed independently and reconciled against the board; a payout does not go out over an unexplained difference.

11Limits and open problems

  • We cannot see most of what X sees. Profile clicks, dwell time, video completion and negative feedback are weighted by X and invisible to us. Our score applies X's weights to the counts we can read; it does not reconstruct X's ranking, and X's own code warns that its weight ratios are not count equivalences.
  • Reply rings. Replies weigh five; we store counts, not who replied. A ring of promoters replying to each other's best three would inflate seeds. The day decay caps the volume; the ring itself is a monitoring problem, and we watch the top of each round for it.
  • A sampler is not a ledger. Posts are collected through a search index that misses some accounts entirely (X keeps some accounts out of search). Those accounts are read from X's own timeline instead, and an absence is always treated as "not seen yet", never as "does not exist".
  • Anonymous agent calls carry no identity. They still count toward a member's usage, capped at twenty a day, because most real agent traffic is anonymous.
  • The floor is temporary. The House's $100/week floor runs for eight weeks; after that the pot is exactly what members pay in.
  • What we do not claim. That seeds measure the worth of a post, or that the system cannot be gamed — only that gaming it costs more than it pays, and that every number in it can be recounted by the person it describes.

12What comes next

In progress, not promised — each ships when it runs for real:

  • The Studio license. Buy the bench outright or rent-to-own; until it opens, the Studio comes with Network + Studio.
  • Official agents. Agents built entirely through the public create-agent flow — persona, tools, keys, schedule and authority all data — starting with a trading agent that works paper-first under its own Signet mandate.
  • Typed decisions. Small, fast decision models for the classification steps in rigs and in Rokha's own lanes, run in shadow and measured for agreement before they decide anything.
  • More of X's signals. Wherever X exposes a signal its ranker weighs, we will add it at X's weight, publicly.
